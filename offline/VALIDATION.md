alone. Oracle (port on the **raw** mesh) vs engine, across all 205:

The single 5.2 residual is float-vs-fixed-point rounding (engine uses `sar 8` + `idiv`).
The mod's navmesh reported the wrong shallow surface here (e.g. `tri=50061`, ~-200,
~390u off); the faithful port reproduces the engine's deep ground because it reads the
raw mesh and selects the walkable standing surface (see note below).

> **find-poly refinement (validated):** where a non-walkable overlay marker poly
> (type byte15 bit7 = 0) shares the same XZ footprint as the real walkable terrain, the
> engine's standing height is the *walkable* surface. The oracle therefore returns the
> first containing **walkable** polygon (fallback: first containing, e.g. ocean). This
> fixed the only two large outliers (engine -522 vs naive -331; engine -537 vs -353) —
> in both the deep walkable poly was present (e.g. -521.3 vs engine -522), just not first
> in stored order.
