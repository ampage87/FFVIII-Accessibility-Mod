## Architecture, safety & workflow rules

- Read **`DEVNOTES.md`** + **`NEXT_SESSION_PROMPT.md`** at session start; `DEVNOTES_HISTORY.md` only when tracing past decisions. Update both at every version bump AND after every BAT.
- **Version bump = ONE place:** `FF8OPC_VERSION` in `src/ff8_accessibility.h`, paired with a new top `CHANGELOG.md` entry; `push_to_github.ps1` refuses if the top `## vX.Y.Z` ≠ the macro.
- **Filesystem MCP for Windows project files.** `filesystem:edit_file` CORRUPTS on a literal `$` in the replacement — use hex `0x24` or `write_file`. OneDrive throws transient EPERM on rename — retry once. (Cowork Read/Edit/Write also work; its bash sandbox mounts the project, so grepping logs there is fine.)
- **NEVER re-enable the SET3 hook (0x1E)** — interception hangs the infirmary scene. CI-guarded.
- **Victory/transition TTS hooks the text renderer, NOT memory.**
- **F-key handlers gated on `!(GetAsyncKeyState(VK_MENU) & 0x8000)`** (no Alt combos). **F12 = per-session diagnostic ONLY** — grep `VK_F12` and remove old code before hooking a new one.
- **Source size (CI guard):** 60 KB soft / 80 KB hard. Split via textual `#include` of `.inl` from the parent `.cpp` (no header guards/namespaces inside `.inl`; `*_state.inl` statics first). **Split BEFORE the edit that needs the room, not by shaving comments to fit** (`.286`–`.293` deleted explanation until `.294` had to split anyway). **Prove a split inert**: reconstruct the pre-split file from the fragment, build both, diff real output. **NEXT UP: `field_navigation.cpp` at 81,792/81,920 — split it before anything else lands there.**
- **Diagnostics:** gate behind `#define X 0`, don't delete.
- **GitHub commit history is authoritative** — `github:list_commits` before quoting push state.
- **Position resolvers** (`ResolveLatePositions` → `MatchSet3LateCaptures` → `ResolveStructPositions` → centroid): the first three read live entity structs and silently return ANOTHER entity's data for out-of-window slots. Guard = reject a live read whose triangle ≠ the entity's own static SET3 triangle, in **both** struct-reading passes (`.290` guarded one, `.291` fixed it).
- **Entity-catalog identity:** SYM names are unreliable (kanban2 was Xu) — never expose them, and **never map a SYM to a friendly name because it reads like one** (`.288` mapped `ladline*`→"Ladder" on spelling; `ladline7` was the gate blocking Aaron, hidden 3 BAT cycles). Name only on behavioral evidence (sole entry reaching "In range." at the object; SETMODEL id shared with a known gate). `ResolveFriendlyName()` NEVER returns empty — on a miss it returns the capitalized SYM, so "just remove the row" leaks it; check `ENTITY_DISPLAY_NAMES` explicitly. `ENTITY_SKIP_NAMES` must be checked for JSM-injected objects too, not just Backgrounds. NPC/interaction labels are generic ("NPC N" / "Interaction N") only. Announce-time counters need TYPE-based matching for JSM-injected entries (entityIdx ≤ −300), not the legacy `entityIdx ≥ 0` test.
- **Navigation is screen-relative** (v0.17.0): cardinals map to arrow keys; project through `s_camRight/Down` before `atan2`. **F9 auto-drive uses `s_camRight/Down`** (quantized at load); **chase-drive uses `s_driveCam*`** (CALIB) — don't cross the streams. **F9 corridor steering is OFF** (v0.17.6.2).
- **EWM/battle-menu TTS are load-bearing.** EWM preserves "first-to-fill acts first, no skipped turns, natural ally/enemy ratio". Mechanical splits only unless Aaron approves.
- **Arrival detection / coord capture need the underlying decision VERIFIED, not just signal-presence.** Mid-drive replan must honor the same planner-eligibility gate as initial Start; when "fixing" a planner decline don't substitute a different region (the v0.14.95 mistake).
- **A catalog category can empty mid-visit.** Trigger lines are captured once on field entry; after a battle `[LINE-PAIR] captured=0` and every trigger-line exit disappears (#88). Before blaming a code change for "X vanished", check for a battle and compare against the FIRST field-entry block in the log.
- **Fields have STATE** (`.293`–`.297`, ENABLED). Entities can be alternate world-states of ONE object, gating `SET3` on a shared varblock vs different values; the catalog is built from STATIC data so it would inject every state at once → phantom duplicates. Three-part rule, all three parts load-bearing: **(1)** only a CONDITIONAL entity may be suppressed — a `JPF` (0x02) between the guard read and the `SET3`; without one the `SET3` always runs and the guard feeds a later branch. Not a SYM-name split (glwater2 `saku2` is conditional, `ladline6` is not). **(2)** the group must be ANCHORED — some member's value equals the live byte; otherwise the variable isn't encoding this group's state in a way we understand, so leave it alone (this is what keeps glwater2's three coexisting gates safe). **(3)** then suppress conditional members whose value ≠ live byte. Skips catalog INJECTION only; position data stays intact. A shared varblock does NOT imply mutual exclusion — a naive equality rule would have deleted Gate 3, which the `.295` dry run caught before it shipped.
- **One change per BAT cycle.** If a fix doesn't engage, READ THE LOG first; identical outcomes across "fixes" mean the diagnosis is wrong; when stuck, ask Aaron for one specific observation. His domain knowledge is ground truth but his recipes need verification. **When a fix targets one of several passes writing the same field, check ALL of them.** **Ship a diagnostic, not a guessed fix, when the mapping is inferred** (`.293`).
- **Logs:** `ff8_field.log` is large — bash-grep it. `ff8_nav_data.log` logs every player triangle change. **F11 screenshots are gold** — comparing two shots of the same room across saves is what revealed the fallen-ladder state (`.293`). `[MAPJUMP-HOOK]` = live engine oracle for exit destinations. **`[NAV-PROJ] start ... player=(x,y)` gives Aaron's exact position** — measure catalog entries against it before theorising about what's missing.
